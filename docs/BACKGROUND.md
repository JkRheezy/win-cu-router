# 背景、优势、代价与边界

本说明适用于 `0.1.0-alpha.2`，整理于 2026-09-21。它回答“为什么做”“已经证明什么”“还不能证明什么”；操作步骤见 [README](../README.md)。

## 问题背景

本项目最初研究如何在 Windows 中采用 Jev-cu 的工作分工：让小型结构化决策模型处理有明确候选项的步骤，复杂规划和视觉判断留给宿主，输入则交给已有的 Computer Use 执行层。

Jev-cu 已给出 Jev 与官方 CU 结合的实现示例；Jev Ultrafast 已演示结构化网页观察、动态候选与独立核验。这些是本项目的直接启发，不能作为本项目原创架构宣传。[Jev-cu 原始说明](https://github.com/Sac-Y/Jev-cu/blob/38fb31de7dfe6209bbe6e04057c00c6e885ba577/README.md)、[Jev Ultrafast 原始说明](https://github.com/browser-use/jev-ultrafast/blob/1231850a0bf1a0c0341fe408ef1668dbbfdfac46/README.md)

Windows 并非没有无障碍树。本机通过 trycua 获得过计算器和记事本控件；某个 App 或某条调用路径返回少量控件，不足以推断 Windows、官方 CU 或 trycua 整体不支持。另一方面，控件存在也不代表所有文本、画布、弹窗和交互都能可靠读取。[本机观察证据 E06](evidence/local-validation-2026-09-21.json)

## 为什么采用当前组合

一次电脑操作的耗时可能包括观察、文字/图像整理、模型往返、执行、等待与核验，还受进程启动、网络和宿主调度影响。该分解是分析方法，不是每项均已测得的成本模型。

前期对比曾混用逐步宿主调用和常驻本地循环，不能据此判断哪一个执行器天然更快。因此当前选择将观察、决策和执行分开，保留 trycua 与官方适配的可比较入口。历史原型上的比例不作为本版提速指标；本文也不声称本版已经完成严谨的同构性能基准。

当前选择 trycua，是因为本机 driver 已提供可调用的结构化 UIA、浏览器语义、截图和核验接口。统一观察层主要是对这些现有能力的连接管理与数据封装，而不是另一套自行研发的视觉或无障碍引擎。Jev 的判断能力来自 TypeSafe，官方点击能力来自宿主插件。[代码与归属](../PROVENANCE.md)

## 优势与事实依据

| 当前优势 | 已有事实 | 可以得出的结论 | 不能推出的结论 |
|---|---|---|---|
| 相同观察接口可被多个任务复用 | 计算器、记事本、浏览器通过同一封装读取，E06 | 新增任务不必重新编写底层 UIA/DOM 读取器 | 所有 App 都已支持，或上游 21 项读取都已完整测试 |
| 有结构的步骤可以交给 Jev | `6+7` 和网页字段输入自主通过，E02、E03 | 这两个有限例子可由 Jev 驱动 | 可独立完成任意长链办公任务 |
| 单次结构化读取开销较低 | 两个原生 UIA 样本为 168/151 ms，浏览器结构加截图为 242 ms，E06 | 这些路径在本机具有用于交互循环的潜力 | 每步或每项任务都只有这些耗时；本项目创造了驱动读取速度 |
| 动作和完成状态都有检查入口 | runner 的状态变化检查、verifier 与过期引用测试 | 某些已知失败可被检测并交回宿主 | 检查逻辑覆盖全部误操作、状态竞争或权限风险 |
| 可以研究不同执行组合 | alpha.1 有官方执行样本，alpha.2 有 trycua 执行样本，E01–E03 | 架构允许分别检验执行路径 | 因任务、版本和动作数不同，这几行可以直接计算提速倍数 |

表中 E 编号对应[公开脱敏摘录](evidence/local-validation-2026-09-21.json)。原始日志是维护者本机记录，尚无第三方独立复现；摘录和哈希提供可追溯性，不构成独立认证。

## 劣势与实际失败

| 代价或不足 | 事实依据 | 当前处理 |
|---|---|---|
| Jev 仍可能对简单导航要求接管 | Success Stories 导航曾低于 0.65 阈值；阶段提示后也发生接管，E05 与验证记录 | 保留失败，不调低阈值来凑成功；由宿主明确继续 |
| 每步仍有网络请求与核验开销 | 搜索框一次输入完整循环 3.168 秒；算式五次动作 11.762 秒，E02、E03 | 不以读取耗时冒充任务时间；尚未证明总体费用更低 |
| 网页能力还依赖任务配置 | BrowserTask 使用明确的 clickNames、固定 fields 和完成条件 | 这是有限任务策略；尚未实现 Ultrafast 那样的动态文字生成链 |
| 观察可能不完整或短暂滞后 | 浏览器返回过 partial snapshot；标题曾滞后为 about:blank | 保留分页/缺失信息，按页面结构判断可读性；不是补全所有页面内容 |
| 会话恢复不能恢复页面内容 | 结束隔离浏览器所属会话后原浏览器进程消失，E09 | 活跃服务续期；失效后明确恢复或重建，不重放输入，不伪称找回表单 |
| 混合执行仍需适配 | 官方 sky 适配只处理经校准的 click 矩形 | DOM ref 不能直接当官方控件索引，任意 App 输入仍需策略与测试 |
| 增加维护面 | Node.js、Python、driver、远程模型与可选宿主插件的组合 | 记录验证版本和失败路径；没有多版本或长期运行保证 |

## 适用边界

**已实现并有代表性实测**：限定窗口观察；有界网页观察；中文计算器有限算式；网页固定文字输入；接管返回与局部会话恢复机制。

**已接入但未全面验收**：21 项读取能力中的所有正向路径、不同浏览器配置、多窗口长期切换、所有部分树/分页/缩放组合。桌面全屏读取和剪贴板接口默认关闭；是否能读与是否应读由任务范围决定。

**尚未完成**：原生记事本编辑全流程、文件选择、Office 保存、任意网页控件、通用自动 GPT 接管执行、自动截图理解、自动文本生成和游戏操作。支持返回图像，不等于已把图像转成 Jev 可用语义。

**不是操作系统安全边界**：HTTP 的认证和范围验证限制本接口的使用方式；拥有本机进程或代码执行权的宿主仍需自己的权限管理，模型置信分数不能替代授权。

**不是官方发行或合作项目**：没有把官方运行时打入包中，没有继承供应商商标/服务权利，也没有用联名标志暗示背书。本项目新增代码采用 MIT，外部组件和服务仍分别适用其条款。

## 下一步需要什么证据

要证明“更好用”，需要先固定任务与结果条件，再记录成功、失败、接管率、动作数、模型/执行/观察耗时和总费用；在同样的起始状态、机器、窗口和核验条件下交替重复不同路径，并保留全部尝试。跨应用和长时间运行应另设验收，不从单次计算器或网页输入推断。

这是后续评测要求，尚未全部完成。当前可复现入口、记录来源和计时界限见[验证文档](VALIDATION.md)。
