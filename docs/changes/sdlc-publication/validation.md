# 首次远程发布的验收范围

这次变更把原有本机检查连接到可发布流程。验收分两层：本提交的机器检查与宿主审查验证流程控制；随后实际创建仓库、PR、CI、发布和维护演练的远程结果，以后续回流任务记录为准。

- A1/A2：`test/sdlc.test.mjs` 覆盖缺失/过期审查、缺失验收证据、未解决发现和超范围修改；`check-sdlc.mjs` 对真实 Git diff 与公开源码指纹执行同一规则。
- A3：`scripts/smoke-package.py` 在隔离目录从白名单 ZIP 运行 demo、完整 JS/Python 测试和文档检查，不使用源码工作区内的模块副本。
- A4：`release-gate.cjs` 查询当前 main 与 test.yml 的真实运行记录；拒绝分支、版本不符、旧 SHA 或只有 PR 验证的情况。对应负例由单元测试覆盖。远程发布还需此门禁真实通过。
- A5：维护处理器按工作流与提交去重，创建 Issue 的同时写 intake；测试验证重复调用复用 Issue、正文保持不可信数据。远程手动演练明确标记为 drill，不计为产品故障。

审查方式为编写代码的宿主自查。此变更不增加真实 CU 能力、不更新旧桌面样本的计时，也不把离线测试数量当作办公成功率。Hooks 的信任状态已查证，自动事件触发仍未留证；云端流程不依赖它。
