# Hooks 启用核验与路径检查修正

## 意图与范围

用户已在 Codex 中信任项目 Hooks，要求继续。核验现有配置，修正检查程序的误判，并更新本地工作流状态；不更改信任记录，不新建对话，不启动额外模型回合或上传仓库。

## 发现与处理

原私有检查脚本用 `Path.resolve()` 将配置中的项目路径转换为 Windows Junction 的实际目录。本机相同目录通过两个路径访问时，`hooks/list` 返回了不同的来源路径与信任结果：已添加的项目路径为 trusted，实际目录别名仍为 untrusted。之前的检查并不代表用户没有启用。

新增 `npm run check:hooks`，默认保留当前工作目录的路径拼写，也可用 `-- --cwd <项目添加时的路径>` 明确选择。检查只调用 initialize 和 hooks/list，分别检查两个必需事件的 enabled/trusted，并保留加载错误。不会复制信任条目或自动信任另一条路径。

## 验收与证据

- 按已配置的项目路径查询，SessionStart、Stop 均已启用、受信任，加载错误为空。
- 路径别名、只启用未信任、缺失事件和加载错误不能误报为就绪。
- 状态查询与实际事件触发分别记录；尚未观察到的事件不写成已执行。
- 更改后运行 `npm run verify`，检查文档与源码包，记录审查结果。

实际 `npm run check:hooks` 已通过，返回两个 enabled/trusted，加载错误为空。脱敏证据见[启用记录](../evidence/hooks-activation-2026-09-21.json)。26 项离线测试、文档链接与发布扫描通过。

尝试通过原生 app-server 恢复现有项目任务来观察 SessionStart；宿主因任务已有活动写入者而拒绝恢复。没有强制接管、没有新建任务或启动模型回合，也没有收到事件触发通知。因此只认定 Hooks 已被正确加载、信任并具备执行条件；自动生命周期触发仍未被本次试验验证。

宿主自查重点为路径范围、信任不被自动扩大、状态与执行证据不混淆；未做独立审查。Hook 定义未变，用户不需因本次检查脚本修改而重复信任同一定义。
